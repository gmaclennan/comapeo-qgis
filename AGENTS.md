# AGENTS.md: comapeo-qgis

QGIS plugin ("CoMapeo") that shows CoMapeo project data as QGIS layers by talking to CoMapeo Desktop over the local API. Design: `docs/PLAN.md`. Wire contract: `../comapeo-local-api/docs/PROTOCOL.md`, which is the source of truth; never code against behaviour it does not state.

OSGeo4W's `python-qgis*.bat` resets `PATH` and `PYTHONPATH`, so `COMAPEO_NODE` names Node there.

## Rules

- Runtime dependencies: Python standard library, `qgis` and `qgis.PyQt` only. No pip packages, no binaries. Import Qt only through `qgis.PyQt`, never `PyQt5`/`PyQt6` directly.
- One codebase for QGIS 3.40+ (Qt5) and 4.x (Qt6): use scoped enums (`QLocalSocket.LocalSocketState.ConnectedState`), `exec()` not `exec_()`, `errorOccurred`.
- Python 3.9 syntax and standard library at most (QGIS 3.40 allows 3.9): no `match`, no `X | Y` outside annotations, and catch `socket.timeout`, which is not `TimeoutError` before 3.10.
- `core/` must never import `qgis` or PyQt; `tests/test_packaging.py` enforces this.
- Tests check behaviour through public surfaces (bytes on the socket, the core API, resulting QGIS layers), not private functions or mock call counts. Prefer real sockets and real QGIS objects over mocks.
- Unix socket paths must stay under about 100 bytes: tests use `tests.fake_server.short_tempdir()`, not pytest's `tmp_path`.
- Cache downloaded media by attachment key and variant, never by URL; the media server port changes every launch. The attachment lists stored in the cache rows keep the URLs from when the row was written: never fetch from them. When the app is connected, ask it again (`layers.getFeatures` with `ids`) for current URLs.
- Every asynchronous media result in the panel is checked against the selection it was started for (a generation counter); a late reply must never show under a newer selection.
- Only `http` URLs on a loopback host are fetched (`core.media.is_media_url`), with no proxy and no redirects. Attachments keep URLs only for the variants the media cache knows (`core.model.MEDIA_VARIANTS`: thumbnail, preview, original), dropped when parsed, and `MediaFetcher.fetch` refuses any other.
- Comments only for a non-obvious why, one line.
- QGIS tests wait with `wait_until` (runs the Qt event loop), never `time.sleep`. They compare QGIS layers with what the server serves over a second connection (`tests/qgis/helpers.Oracle`), not with the plugin's own state. Tests never touch the real QGIS profile (conftest asserts it) and point discovery at an empty folder unless they start a server.

## Gotchas

- Cache tables carry private columns (document id, version, category id, attachments) whose names are chosen per table against the server's column names, case-insensitively, because SQLite compares names that way and any tag key may arrive (`fid`, `geom` included). The renderer keys on the category id column, never the translated category name.
- A map layer is CoMapeo's only when it is an `ogr` layer on a file named after its project id (`cache.cache_file_name`) and carries the `comapeo/projectId` and `comapeo/layerId` custom properties (`layers.comapeo_ids`). The properties alone are not enough: Copy/Paste Style or a QML file copies them onto any layer. In plugin code, decide ownership through `comapeo_ids`/`comapeo_layers`, never by reading the properties directly. Within a project the table wins over `comapeo/layerId` (a style pasted between two CoMapeo layers brings the other's id): the controller's `_resolved_ids` corrects the property from the table the layer is on.
- A schema change creates a new table (`<layer>_<hash of layer id and schema key>`), staged (`staged:<id>` in `comapeo_meta`) while map layers stay on the old one. Only after the full fetch succeeds is it committed, map layers switched with `setDataSource` (carrying the user's `subsetString` across) and the old table dropped; a failed fetch leaves the old table and its refresh time. Saved QGIS projects that still point at a dropped table are re-pointed on load from the layers' `comapeo/projectId` and `comapeo/layerId` custom properties. `Controller.ensure_table` returns any stored table as it is and leaves rebuilds to the sync.
- GeoPackage has no list type: `string_list` columns are stored as JSON; QGIS 4.0 and 4.2 read them back as a `QStringList` field of subtype JSON, and 3.44 gives the same values.
- After writing through the cache's own provider, map layers on the same table need `reload()`; `featureCount()` is stale until then.
- The OGR provider does not convert geometry dimensions: write Point 2D and LineStringM (NaN where a time is missing) to match the table.
- Browser items: QGIS owns what `createChildren` returns, so each child is passed to `sip.transferto(child, None)`. Collections keep the `Fertile` capability: without it `QgsDataItem::refresh` recurses into a kept child with the children of a temporary copy, adopts them, and the copy's destructor then deletes them, so the next refresh crashes QGIS (seen only in a real window, where the tree is expanded while projects and layers arrive). With `Fertile`, QGIS refreshes one level, so the provider refreshes every expanded collection itself. Layer items are created `Populated` so they show no expand arrow. Nothing on the C++ side keeps the Python half of a grandchild alive, so the provider holds a reference to every item it makes (pruned once QGIS deletes it); without that, items reached through `QgsBrowserModel` silently become plain `QgsLayerItem`s. Never call `QgsDataItem.children()` from Python, in plugin code or tests: under PyQt5 (QGIS 3.x) it returns new Python-owned wrappers, and when the list is dropped they delete the C++ items still in the tree, which crashes QGIS later. Collections record the children QGIS keeps (`_Collection.held`, mirroring `QgsDataItem::refresh`, which keeps an existing child equal to a new one). Test the Browser through a real `QgsBrowserModel` (`tests/qgis/test_browser_model.py`), not by calling `createChildren` or `children()` from Python.
- A damaged cache (`ProjectCache.is_damaged`: SQLite says it is not a database, malformed, or lacks `comapeo_meta`; a lock or a permission problem is not damage, and the check does not wait on a lock) is renamed aside (`set_aside_if_damaged`) before anything writes to it: when the app lists the project, before that listing writes metadata, before a sync attaches and before a sync writes a new schema, so the rebuild never writes into it. The answer is remembered only while the file and its `-wal` keep their time and size (with the file open in write-ahead-log mode a change may touch only the `-wal`), and never when a lock or another error kept SQLite from telling. The exception is Windows, which will not rename an open file: a damaged file that is still a GeoPackage (one lacking `comapeo_meta`) is held open by the reopened map layers, so it is repaired in place. Copies set aside within one second get a numbered name rather than overwriting each other. `cached_projects` also lists damaged caches of projects on the map, since their name cannot be read from the file.
- A cache another program holds a lock on: GDAL waits 5 s (its `SQLITE_BUSY_TIMEOUT`) on every open of a locked GeoPackage, on the main thread. So the plugin reads the cache (metadata, versions, attachments, `project_in_file`, the damage check) with Python's `sqlite3`, read-only and without waiting, and before any write through OGR checks with a `BEGIN IMMEDIATE` probe that waits at most 0.25 s, raising `CacheLocked` (a `CacheError`) otherwise. Metadata unread because of a lock is never remembered: the status says the data is in use, `is_stored` assumes the table is there, and the 10 s poll re-reads. A sync stopped by a lock keeps the work it was doing and tries again by itself (`sync.LOCK_RETRY_MS`, doubling up to 8 s), clearing the lock's message once a fetch gets through. What remains outside the plugin: QGIS itself opening a saved project's layers on a locked file waits 5 s per layer. Reading with `sqlite3` beside GDAL is safe only while both use the one SQLite library in the process (true of the macOS app, which links both to its own `libsqlite3`); two copies would release each other's POSIX locks.
- Windows will not delete a file that is open. Map layers removed from the project close their GeoPackage only when deferred deletes run, so `remove_cached_data` flushes them and retries once.
- Windows: Python has no `AF_UNIX` there, so `tests/fake_server.py` and `tests/driver.py` use `tests/winpipe.py`, byte-mode named pipes with overlapped I/O behind a socket-like interface; the oracle in `tests/qgis/helpers.py` uses `QLocalSocket`. Only tests of POSIX file permissions, and of process liveness through a POSIX socket file, skip on Windows. A dialog in a headless run blocks forever, so `tests/qgis/conftest.py` makes any unexpected `QMessageBox` fail the test.
- `FrameDecoder` refuses a frame whose JSON nests deeper than `MAX_JSON_DEPTH` (64), because Python 3.14 parses nesting that older versions reject with `RecursionError`. The depth is checked after a successful parse, as the scan's string pattern is very slow on an unterminated string, which the parser rejects quickly.
- The protocol has no notification for projects joined or left, so the controller re-lists projects every 10 s (`PROJECT_POLL_MS`); a poll only acts on projects that appeared, disappeared or were renamed, never refetching the ones on the map.
- Discovery: the installed builds' data folders are listed in `core/discovery.APP_FOLDERS`. A development build of desktop is not among them (its data is in its checkout), so it is found only through an extra location: the panel's "Other app locations…" (setting `comapeo/extraDiscoveryPaths`) or `COMAPEO_LOCAL_API_DISCOVERY_EXTRA`. Each extra location is a build keyed `extra:<location>`, with the location tidied first (trailing and doubled separators and `.` steps dropped) so one folder spelt two ways is one build. At each scan the connector closes the connection of any build no longer among the locations looked in, so removing an extra location, or setting the override, takes effect while that build is connected. The override (`comapeo/discoveryPath` or `COMAPEO_LOCAL_API_DISCOVERY`) replaces every location, extras included; tests rely on that never to read a real app's folder, so keep it that way.
- `layer.reload()` drops the user's selection; the controller re-selects the same documents (`_reload_keeping_selection`), otherwise every refresh would clear the media panel.
- Media downloads: a reply can fail after a 200 header (app closed mid-file, transfer timeout). `MediaFetcher` keeps a file only for a 200 with no network error and either the full Content-Length or chunked framing. Core's blob server (7.7.0 and earlier, so today's desktop) sends no Content-Length for a plain GET, only `Transfer-Encoding: chunked`, and Qt reports a chunked body cut short as an error. A 200 with neither is never kept: only the closed connection ends it, so a cut-off one looks complete. Anything not kept is deleted and recorded as an error, which Refresh, an app connecting and a fresh attachment list for the selection all clear.
- Audio on Qt5: Qt5 has its own `QAudioOutput`, a raw PCM sink unrelated to `QMediaPlayer`, so `audio.py` picks the Qt6 path by `hasattr(player, "setAudioOutput")`. PyQt5 passes player states as plain ints: compare them with the enum (`QMediaPlayer.PlaybackState` on Qt6, `QMediaPlayer.State` on Qt5), never by `.name`.
- Audio: under `QT_QPA_PLATFORM=offscreen` (the pytest runs) QMediaPlayer stays in `LoadingMedia` on macOS and never plays, so pytest only checks the control and the cached file. Playback is checked in the real-window media smoke run, which samples state and position. Tests open files through `QDesktopServices.setUrlHandler("file", ...)` (the `opened` fixture), so no viewer is ever launched.
- Editing: QGIS's own commit never writes to the cache. `EditHook` handles `beforeCommitChanges`, the only signal before QGIS writes: it reads the buffer (a deleted row is hidden from the layer, so ids, versions and forks come from the provider), empties the buffer by undoing the whole undo stack, sends the requests and blocks on the plugin's own socket (`LocalApiClient.wait`: waitForReadyRead, no event loop) for `SAVE_WAIT_S`. To stop a save and keep the edits it adds a feature of the wrong geometry type, which fails QGIS's pre-write check, and restores the edits on the next event-loop turn. Raising in the slot does not stop a commit, `rollBack()` in it crashes QGIS, and `setAllowCommit` is not in the Python API. The hook mutes its own signal handlers while it undoes or restores, so that neither releases the layer's hold nor records a new base version. Everything before the buffer is emptied runs under one `try`, ending in a refused save, and the checks run again after the large-save question, which spins the event loop. A geometry change is undone on the next event-loop turn (`QUndoStack.undo`, when the stack has grown by exactly the command that made it); the save still drops any geometry change that is left, as a backstop.
- A wait on `QLocalSocket` that times out emits `errorOccurred(SocketTimeoutError)`; the transport ignores it, otherwise the connection would close mid-save.
- The version and forks sent with an edit are those the row had when first changed in the session, recorded from the provider. While a map layer has unsaved edits, or a save has replies outstanding, the sync holds that layer (`ProjectSync.hold`): no fetch and no table switch, so rows cannot change under the user; `layers.list` and `categories.list` still go through, and queued work runs on release. Replies are written with `apply_edit_results`, which is allowed while held and falls back to a fetch when the cached row is no longer at the revision the edit was based on.
- What may be edited comes from the connected app's latest `layers.list` (`Controller.live_definition`), never from the cached definition: the editing flags are not part of `schemaVersion`. `Controller.edit_state` decides whether a layer is editable (connected, flags allow it, the table has the private `forks` and `editable` columns and has finished its first download, no transaction groups); `configure` sets read-only, locked columns, value maps and the Category chooser from it. `setReadOnly` cannot change during an edit session, so a session the app stops allowing is warned about and refused at save. A read-only layer greys out Toggle Editing, so `EditHook`'s warning at the start of a session never shows for it: the reason is shown by a lock badge in the Layers panel (`indicators.py`, from `Controller.read_only_reason`) and, unless it is only `unsupported`, in the project's row (`ProjectStatus.read_only`). Date and multiple-choice columns stay locked in the plugin even when the server allows them.
- Greying other devices' rows: the attribute table does not load hidden columns, so a row style on the hidden `editable` column sees NULL. The style reads the flag with `get_feature_by_id(@layer, $id)`. Open tables also keep the row styles they have computed across a reload and listen to no signal that clears them, so after each data change `refresh_not_editable` calls `fieldConditionalStyleChanged` on every open `QgsAttributeTableModel` of the layer. Tables QGIS opens itself reach Python as plain Qt classes (`isinstance` and `findChildren(QgsDualView)` find nothing), so the models are found by `metaObject().className()` and `sip.cast`; a view made in Python, as in the tests, does not show this, and the editing smoke check does.
- Undo everything in a session releases the hold and the recorded versions; a live update can then land, and Redo reapplies the user's edit on the newer version without a conflict. The table shows the newer values meanwhile, so this is accepted. The revision guard in `apply_edit_results`, the hold while replies are outstanding and the deferred table switch for a held layer back each other up; no test needs each one on its own.
- The schema key carries a cache format (`reconcile.CACHE_FORMAT`), so a cache written before the private `forks` and `editable` columns existed is rebuilt once on connect; `TableInfo` reads such a cache without them, so it still shows offline.
- The plugin's messages for the user go through `Controller.notify`, which logs them, pushes them to the message bar (details behind "Show more") and emits `messageShown`. Tests and the smoke scripts listen to `messageShown`: `QgsMessageLog.messageReceived` does not reach Python in the headless test app or, as seen with QGIS 4.2.3, in a real window, so log-based checks in the smoke scripts see nothing.
- `http.server` looks up the host name on bind, which can take 30 s on macOS; `tests/media_server.py` skips that.
- Several app builds can run at once. The cache records the build that last served a project (`buildType` in the `project` metadata), and a project is reported "No longer available" only once that build has listed its projects without it; while that build is not connected the project reads "Not connected".
